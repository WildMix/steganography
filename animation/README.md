# A secret, in plain sight

Open **index.html** in a modern browser. No installation, build, server, internet connection, or private key is needed. Keep the `animation` folder together when copying it.

This seven-minute, 17-chapter 2D film follows `EMBEDDING_WALKTHROUGH.md`: exactly `HELLO`, a 512 × 512 grayscale image, a shared key, `--strategy balanced`, and `--rate auto`. It includes playback, seeking, speed selection, chapter navigation, an interactive four-pixel example, a real image comparison, technical notes, and a text transcript. It starts paused. There is no audio track; explanations remain visible beside the animation.

## Controls

- **Play / Pause** or **Space**: run or pause the film.
- **← / →**: previous or next chapter. Native controls retain their own keyboard behavior.
- **Timeline**: scrub to any point; scrubbing pauses playback.
- **Chapters** or the five section buttons: jump directly to a topic.
- **↺**: replay the current chapter.
- Interactive controls pause playback so there is time to explore. Resuming returns to the scripted demonstration.
- **Under the hood**: implementation details for the current chapter.
- **Read the whole story**: the complete plain-language transcript.
- The film respects `prefers-reduced-motion` by showing completed diagrams without interpolation. It pauses when its tab becomes hidden.
- Link to a chapter with `index.html#chapter=11` (chapter numbers 1–17).

## What the data represents

`fixture.js` and `assets/` are generated by the real Python/C++ encoder. The teaching cover is a reproducible mathematical landscape, not a photograph or a statistical-security benchmark. No existing private key, message file, photograph, or research artifact is used or overwritten.

The fixture uses the walkthrough's deliberately public values:

- Key: bytes `00` through `1f`.
- Salt: bytes `20` through `3f`.
- Padding: bytes `40` through `49`.
- Original and stored message: `48 45 4c 4c 4f`.
- Selected rate: `0.0025`; total allocation: 81 bytes / 648 target bits.
- Plaintext frame: 18-byte header + 5-byte message + 10-byte padding = 33 bytes.
- Authenticated ciphertext: 33 bytes + 16-byte tag = 49 bytes, whitened before embedding.
- Separate salt: 32 bytes. Bootstrap/body pools: 32,768 / 229,376 positions.
- This fixture changes 72 pixels, each by exactly one. That count is specific to these inputs.

The four-pixel equation example and its four-state trellis are intentionally small teaching models. The real encoder uses a structured matrix with overlapping groups and up to 1,024 active states. Cost and change maps use real fixture data; change markers are enlarged for visibility. The balancing score is the actual implementation's objective, not a detector probability.

The real code computes cover costs before constructing the encrypted body; the film groups the explanation by concept. Extraction reads the encoded message, not the original cover. Authentication checks the payload/context, not every image pixel. Visual similarity and low cost do not prove undetectability.

## Rebuild the example

From the repository root, with its Python dependencies and native library already installed:

```powershell
.\.venv\Scripts\python.exe animation/generate_fixture.py
```

This replaces only `animation/fixture.js` and the three generated PNGs in `animation/assets/`. It verifies exact PNG pixel preservation, full HELLO extraction, both syndromes, unit changes, and protected pixels. Ciphertext and pixels are deterministic; the recorded elapsed runtime can vary.

## Verify the browser experience

With Node.js 22+ and an existing Chromium/Chrome:

```powershell
# Optional if Chrome is not in the local Playwright cache:
$env:CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
node animation/verify-browser.mjs
```

The dependency-free check launches a hidden headless browser and opens `index.html` as a local file. It verifies every chapter, all 16 toy flip patterns, budget arithmetic, interactive controls, playback, end/replay, SVG bounds, keyboard navigation, narrow layouts, deep links, reduced motion, and the absence of JavaScript errors or HTTP requests. Screenshots and results go into the ignored `artifacts/animation/` directory. It uses a separate browser profile there.
